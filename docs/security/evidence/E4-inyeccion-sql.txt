# E4 — Inyección SQL (Semana 8) — 2026-11-10T07:02Z
Base: https://securefin.local/api/v1 (vía Nginx). Cada POST lleva su token CSRF, como haría un navegador.

## 1. Login: bypass clásico
POST /auth/login {"email": "' OR 1=1 --", "password": "x"}
→ 401 {"error":{"code":"auth_failed","message":"Credenciales inválidas o demasiados intentos. Inténtalo más tarde."}}
POST /auth/login {"email": "admin@lab.securefin.local' --", "password": "' OR '1'='1"}
→ 401 {"error":{"code":"auth_failed","message":"Credenciales inválidas o demasiados intentos. Inténtalo más tarde."}}
POST /auth/login {"email": "x' UNION SELECT password FROM iam_user --", "password": "x"}
→ 401 {"error":{"code":"auth_failed","message":"Credenciales inválidas o demasiados intentos. Inténtalo más tarde."}}
POST /auth/login {"email": "x'; DROP TABLE iam_user; --", "password": "x"}
→ 401 {"error":{"code":"auth_failed","message":"Credenciales inválidas o demasiados intentos. Inténtalo más tarde."}}

## 2. Campos extra y tipos inesperados (asignación masiva)
POST /auth/register {..., "role": "admin"}
→ 400 {"error":{"code":"validation_error","message":"Campo no permitido.","fields":{"role":["Campo no permitido."]}}}
POST /auth/login {"email": {"$ne": null}, "password": "x"}
→ 400 {"error":{"code":"validation_error","message":"No es una cadena válida.","fields":{"email":["No es una cadena válida."]}}}

## 3. Rutas protegidas sin sesión (filtros e identificadores con SQL)
GET /admin/users?role=' OR 1=1 --
→ 401 {"error":{"code":"auth_failed","message":"Credenciales inválidas o demasiados intentos. Inténtalo más tarde."}}
GET /users/1' OR '1'='1/profile
→ 401 {"error":{"code":"auth_failed","message":"Credenciales inválidas o demasiados intentos. Inténtalo más tarde."}}

## 4. La tabla sigue intacta tras el intento de DROP TABLE
usuarios en iam_user: 5

## Por qué no funciona
- Django ORM: todas las consultas son parametrizadas (el valor nunca se concatena al SQL).
- El login responde siempre el mismo 401 genérico (FR-009): ni siquiera revela si el usuario existe.
- Serializers con lista permitida: campos extra (role) o tipos inesperados → 400 (FR-002).
- Rutas protegidas: sin sesión 401 antes de tocar la base; identificadores ajenos o mal formados → 404 idéntico (BOLA).
- La aplicación usa el rol securefin_app, sin permisos de DDL: aunque hubiera inyección, no podría hacer DROP TABLE (R14).
